## Последовательная демонстрация

Из корня `thbd` сначала запустить первую работу:

```bash
cd lab1
docker compose up -d
# После первого старта инициализировать: docker compose up airflow-init
bash scripts/trigger_all.sh
```

Airflow: http://localhost:8080, `airflow / airflow`. Дождаться успешной загрузки `nhl_standings_to_postgres` и `nhl_games_to_mongodb`. Показать DAG с тегом `lab1` и данные ODS.

Затем из корня `thbd` подключить и выполнить вторую:

```bash
bash lab2/scripts/demo.sh up
bash lab2/scripts/demo.sh run
bash lab2/scripts/demo.sh results
```

`run` запускает процессы последовательно и ждёт конкретные новые run_id. Первый — `lab2_ods_to_dds`: сенсоры → очистка → измерения SCD2 → факты, всё в одной транзакции. Второй — `lab2_dds_quality`: сенсор → проверки. Расписание ручное для воспроизводимой демонстрации; DAG должны быть сняты с паузы, скрипт делает это сам.

Результат — PostgreSQL `localhost:5433`, база `nhl_ods`, пользователь `nhl`, пароль `nhlods`, схема `dds`. SQL для защиты — [sql/demo_queries.sql](sql/demo_queries.sql). Airflow-фильтр: тег `lab2`.

Повторная загрузка детерминированно восстанавливает DDS из накопленного ODS, включая SCD-версии. SQL пересоздаёт только DDS; сырые данные сохраняются. Суррогатные ключи могут измениться после полного пересчёта. Перед будущими витринами ЛР3 следует перейти на миграции и стабильные ключи.

Чтобы снова показать только ЛР1, из `lab1` выполнить `docker compose up -d`. Процессы ЛР2 перестанут парситься; записи их старых запусков могут остаться в истории Airflow. Первая и вторая используют общий архив и метаданные, повторное скачивание не требуется.

## Состав папки

- `compose.yaml` — подключение ЛР2 к инфраструктуре ЛР1.
- `dags/lab2_ods_to_dds.py`, `dags/lab2_dds_quality.py` — действующие DAG.
- Старые раздельные DAG измерений и фактов заменены единой атомарной сборкой. Записи прежних запусков могут оставаться в истории Airflow; они поставлены на паузу.
- `processing/warehouse.py` — чтение, очистка, измерения, факты, проверки.
- `processing/scd.py` — построение SCD2 и поиск версии на дату.
- `sql/001_dds.sql` — снежинка и ограничения.
- `scripts/` — воспроизводимый запуск и экспорт.
- `results/` — сохранённые фактические результаты.

Тесты: `cd lab2 && python3 -m unittest discover -s tests -v`.
